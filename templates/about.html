Data Flow & Integrity

1. Transactional Validation

Before a voucher is pushed to Tally, the service checks strict invariants: It ensures the double-entry accounting matches (`Sum(Debit) == Sum(Credit)`), verifying structural balance via database model constraints.

2. Tally XML Compliance

Data is serialized into Tally's expected XML `` structure using Python's `xml.etree.ElementTree`. The generator strictly handles `ISDEEMEDPOSITIVE` logic (Yes for Dr., No for Cr.) and deduces the `PARTYLEDGERNAME` based on transaction side.

3. Idempotent Synchronization

The system inherently avoids duplicating records. Pushes are guarded against vouchers that already bear a `tally_id`. The "Retry Failed" bulk syncer uniquely operates only on `PENDING` or `FAILED` vouchers.

4. Comprehensive Audit Trails

Every external network interaction generates a `SyncLog` record containing the exact timestamp, status, and raw Tally XML response message (`LINEERROR`) guaranteeing flawless offline debugging.
